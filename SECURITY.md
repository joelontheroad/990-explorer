## Reporting a Vulnerability

We take the security of our open-source utilities seriously. If you discover a security vulnerability or weakness (such as path traversal, insecure localhost binding, command injection, or denial of service), please report it responsibly.

### How to Report

1. **GitHub Private Vulnerability Reporting (Preferred)**:
   Navigate to the **Security** tab of this repository on GitHub and select **"Report a vulnerability"**. This creates an encrypted, confidential advisory between you and the project maintainers.

2. **Direct Contact**:
   If private reporting is unavailable, please email the maintainer directly with subject line `[SECURITY] <Project Name> Vulnerability Report`. Do not open public issues for suspected vulnerabilities.

### What to Include

Please provide:
- A description of the vulnerability and its potential impact.
- Step-by-step instructions or a minimal Proof of Concept (PoC) to reproduce the issue.
- The operating system, runtime version (Python or Node), and tool version used.
- Any proposed remediation or patch, if available.

### Our Commitment

- **Acknowledgment**: We commit to acknowledging receipt of your report within **72 hours**.
- **Investigation & Patch**: We will investigate and provide regular updates regarding our progress toward a fix.
- **Coordinated Disclosure**: We adhere to coordinated disclosure. Once a fix is verified, we will release a patched version, publish a security advisory, and credit your contribution (unless you prefer to remain anonymous).
